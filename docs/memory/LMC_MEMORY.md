# LMC 记忆系统

2026-09-15：分段提取出的候选先写入 `cognition.db/lmc_candidates`，保存原始提案、正文、分数、来源和晋升结果。
自动充电、电量、状态快照等机器流水不进入候选表；用户主动交流按内容提取，低于6分也保留。
正式记忆仍需通过重要性等原有门槛。召回优先使用 `lmc_memories`，剩余名额以相关的低重要性候选补充，并按内容和来源去重。
原始记录仅用于提取、来源验证和纠正检查，不再直接作为召回结果；旧 `literal_raw` 参数仅保留调用兼容性。
候选通过关键词相似度检索，待审、失效来源、已晋升候选不进入辅助召回。历史任务未保存的候选无法凭空恢复，需要另行重新提取。

segment 之后只有一个运行引擎：`lmc5-native-v2`。采用 LMC-5 的五轴架构，使用本项目的 SQLite、模型和证据接口实现，不依赖上游 Python 包或 PostgreSQL 服务。

```text
raw_experiences
  → experience_segments + segment_experiences
  → memory_jobs（保留分段输出的持久任务接口）
  → LMC candidates：证据校验、重要性判断、去重、事实版本
  → lmc_memories + lmc_event_context + lmc_sources
  → lmc_memory_coordinates + lmc_memory_relations
  → 全文 / 向量 / 两跳关系 / 体验共鸣 / 原文定位
  → 聊天上下文与回复使用记录
```

## 运行边界

- `ingestion.py` 和 `application/memory_segmentation.py` 保留原始记录、聊天/通话流分段、收尾和任务创建逻辑。
- `extraction.py` 只管理任务租约、失败和重试；任务统一标记为 `job_kind='lmc'`。旧队列的 Episode 标签在升级时转换，分段算法保持不变。
- `lmc.py` 独占候选提示词、候选提交、事实版本和主回复体验写入；`operations/create/append/update` 协议不再接受。
- `lmc_recall.py` 是唯一召回入口；旧 `recall.py` 已删除。
- `lmc_maintenance.py` 管理关系任务、每日衰减、失效关系和只读巡检。运行时分别处理关系、代谢、向量索引和时间线投影，一项失败不阻塞其余项。
- 管理接口、时间线、会话交接、实际回复使用记录、导出恢复都使用原生 LMC 表。

## 五轴和约束

自身发言也参与后台抽取：已发送的活动、选择、计划和承诺按 `self` 保存为
“左然曾说”的证据性记忆，低重要性保留在 `lmc_candidates`。助手原话不能作为
用户事实；`shared` 必须有用户明确提及双方的证据，可附助手回应，未来约定不能
写成已完成经历。后台抽取不能写 E 轴体验坐标。

候选逐条通过 SQLite 保存点校验：单条校验失败只回滚该候选，并在
`lmc_extraction_decisions` 中记录拒绝原因，合法候选仍可保存。全部候选校验失败
时仍进入原有任务重试流程；数据库或租约错误仍回滚整项任务。同一段聊天的
自身活动和双方约定应拆成 `self`、`shared` 两条，shared 必须完整引用用户表达
双方参与的证据；片名等上下文可以另附助手原话，不能归为用户发言。

正式记忆的 `occurred_start` 与候选的 `occurred_at` 当前取引用来源中最早的时间，
不是独立解析的事件发生时间。召回同时提供 `source_times`，逐条列出说话者及
北京时间（`+08:00`）的来源时间，供模型区分发言日期与原话中的“昨天/下次”。
例如 9 月 15 日 21:39 的“选了《情书》”可定位为当晚的自述，不能推断已经看完。

| 轴 | 本地实现 |
|---|---|
| X 时间线 | 来源发生时间、事件身份、持续主线 `thread`；日/周/月/季/年摘要投影 |
| Y 关系 | 有双端证据的类型化关系；安全边两跳扩展，类型权重、边强度及距离衰减；因果、支持和矛盾边进入待审 |
| Z 事实版本 | 同一作用域、同一 `fact_key` 只有一个当前事实；新事实保留前任历史；更早的补录事实进入待审，不能覆盖较新事实 |
| E 体验 | 主回复交付后，以已发送原话为证据写入；后台抽取器不能代写；初始体验字段不可覆盖 |
| M 生命周期 | 活力衰减、保护记忆、过期关系清理、巡检、可靠重试及审计 |

候选重要性为 1–10，6分及以上可进入正式长期存储，仍须通过证据、置信度和风险校验；低于6分保留候选。评分由抽取模型按提示给出，程序执行门槛，并非客观测量。self/user/shared 采用相同尺度，不因独处扣分，也不因双方参与自动加分：1–2 为重复附和；3–4 为琐碎安排；5 为后续意义不明确的具体日常片段；6 为值得跨会话接续的具体经历、选择或待履行计划；7–8 为持续偏好、重要变化或明确边界；9–10 为有充分证据的重大变化或关键安全边界。既有候选不会因门槛修改自动重评分或晋升。

空候选正常结束任务，但不能静默丢弃与已有记忆有关的明确纠正。来源失效、版本不匹配、待审和已替代的事实不会作为当前事实召回。明确查询历史时，旧事实带历史标签返回。

## 原生表

- 正文与证据：`lmc_memories`、`lmc_event_context`、`lmc_sources`、`lmc_revisions`。
- 坐标与关系：`lmc_memory_coordinates`、`lmc_memory_relations`。
- 后台与审计：`lmc_relation_jobs`、`lmc_extraction_decisions`、`lmc_memory_audits`。
- 检索与使用：`lmc_search_documents`、`lmc_fts`、`lmc_embeddings`、`lmc_recall_logs`、`lmc_session_recall`、`lmc_usage_events`。
- 时间线投影：`lmc_calendar_summaries`、`lmc_calendar_sources`。

所有原生表位于 cognition 数据库。传入正式 core 数据库路径创建 `MemoryStore` 时，会将 schema 初始化定位到 cognition，避免备份导入在 core 中重复建表。

## 升级与恢复

记忆已从空库重新开始。启动只初始化原生 LMC，不再迁移或读取旧记忆。

旧建表文件、演化兼容模块、一次性迁移代码和旧备份导入分支已删除。`source_schema.sql` 仅创建原始记录、分段队列和认知审计表。

显式重置入口为 `python backend/scripts/reset_memory.py --apply`，运行前应停止后端；省略 `--apply` 只显示计数。重置清空个人记忆、原始经历、分段、任务和索引，删除旧记忆表，保留聊天、角色语料、情绪与世界业务数据。`memory_reset_at` 阻止旧自习、生活事件及历史聊天再次回填；模型会话也会重新开始。已有备份文件不属于运行记忆，不会自动删除。

私有数据 ZIP 版本为 12，导出原始记录、分段队列、原生 LMC 数据及 Dream 页面、历史篇章和使用记录。导入支持 v10–v12 原生备份（旧包没有的 Dream 内容保持为空）；v1–v9 旧包会在写库前明确拒绝。全文及向量索引、基础日历投影、会话去重缓存可重建；恢复时清除失效租约和本机 Dream 任务。

验证入口：

```powershell
python -m pytest backend/tests/test_lmc_memory.py backend/tests/test_lmc_native_storage.py backend/tests/test_memory_reset.py -q
```

## Dream 与日历叙事

`dream.py` 参考 [kiwi-mem](https://github.com/LucieEveille/kiwi-mem) 的睡眠整合和日历分层思路，独立实现于现有 SQLite LMC 上，不引入额外服务。

- 调度：后台每轮最多处理一个日历任务。用户静默至少 20 分钟后，在左然睡眠期间或北京时间 00:00–06:00 整理；手动请求可在白天执行。先等待待处理的 LMC 抽取任务完成。
- 日页面：基于当天有效记忆生成叙事、场景及暂定理解；可产生有效期最多 30 天的前瞻。睡眠/手动整理允许生成当天未结束的页面，新增记忆后重新生成。空日期不生成内容。
- 层级：日 → 周 → 月 → 季 → 年。高层读取下层模型摘要，只有完整结束的周期才生成。周从周一开始；月边界跨周时用边界日页面，避免混入其他月份或重复统计。错过的周期在下次符合条件时补齐。
- 周/月反思：梳理变化、延续和未解之处，作为暂定理解保存，不升级为用户事实、权限或左然亲历的 E 体验。场景整合不会删除有证据的原始事件，原有关系清理及代谢仍独立运行。
- 可靠性：页面保存全部原始记忆 ID/版本和下层页面签名；发布前复核，新增、失效、敏感性变化及事实替换都会使相关旧页面停止展示与召回。模型调用在事务外执行。任务持久化，租约 30 分钟；失败按 5/10/20/40 分钟退避，第 5 次失败停止，手动请求可重试。大输入分批归纳，不静默截断来源。
- 自发回忆：从一天以前的事件/关系记忆与真实 E 体验中选一条关联，受同样的敏感性、当前纠正及会话去重约束。全局至少间隔 6 小时，同一条至少间隔 7 天。仅进入聊天候选上下文，不自动发送消息；普通寒暄和明确查记忆不触发。
- 白天召回：主题相关的场景、日历摘要、暂定反思及未过期前瞻可以进入上下文；周/月回顾优先给摘要。派生内容带 `reflection` 类型和假设标签，沿用回复校验，不作为直接事实证据。仍受总预算、作用域及来源过滤限制。

管理接口：`GET /memory/dream` 查看页面/任务；`POST /memory/dream` 请求后台整理；`GET /memory/calendar?level=month&limit=50` 查看指定层级。页面包含来源、下层页面、完整周期标志和前瞻有效期。

移动端顶部导航：手记 / 相册 / 信件 / 梦境。手记分为动态、日记、回顾三个独立部分；回顾提供日/周/月切换，按日期查找会包含覆盖该日的高层回顾。梦境直接进入 Dream 历史列表，展开阅读「梦中浮现」「醒后的想法」「想到以后」。日记不混入自动回顾，也不放 Dream 入口卡。季/年摘要仍在后台保留。没有记录、请求失败及更多历史都有独立状态。

`GET /memory/reading?kind=reviews|dreams&offset=0&limit=30&date=YYYY-MM-DD&level=month` 是分页阅读接口，日期和层级可省略。只提供阅读所需字段，不返回内部来源 ID。每次成功的日级整理以任务 ID 为键写入 `lmc_dream_entries`，与当前日历页面在同一事务提交；失败和重试不会生成重复篇章，周/月等高层回顾不冒充独立梦境。后续新增来源不会覆盖旧 Dream；来源失效、修订或变敏感时旧篇章仅展示日期与不可用提示。历史不重新进入记忆召回，也不把总结生成时间当成原事件发生时间。

持久表：`lmc_dream_pages`、`lmc_dream_jobs`、`lmc_dream_usage`、`lmc_dream_entries`，均在 cognition 数据库；显式记忆重置会一起清空。

架构参考：[LMC-5](https://github.com/wuxuyun0606-collab/lmc-5)、[实现顺序](https://github.com/wuxuyun0606-collab/lmc-5/blob/main/docs/IMPLEMENTATION_ORDER.md)。这是面向本应用的本地实现；上游 PostgreSQL 扩展和编码代理 hooks 未引入。
