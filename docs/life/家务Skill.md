# 家务 Skill

家务由粗计划的具体安排或「家务」意图触发。`housework.prepare` 接入统一工具层，确定性选择和保存步骤，不额外调用模型选择刷哪张桌子。

- 饭后收拾：收餐具、洗碗、取抹布、擦餐桌、放回抹布。
- 普通家务：优先继续未完成家务和待处理衣物；否则结合当前房间和近期记录选择整理、擦拭或启动扫地机器人。
- 洗衣：本人放入自用衣物并启动机器；机器按 30 分钟模拟周期独立运行。
- 晾晒：机器洗完才允许本人取衣、走到阳台并晾晒。
- 收衣：按 4 小时模拟晾晒时间标记晾干后，本人收衣、走到清单中的衣柜并叠放。

只能使用运行时家庭清单已确认的物品、设备及位置。房间之间走实际配置路径。未知物品或缺少设备时不虚构；不虚构脏衣件数、污渍或用户衣物。洗衣和晾干时长是模拟参数，不表示实际家电反馈或湿度观测。未调用真实家电。

开始、暂停、恢复、每个实际步骤完成、洗衣机或扫地机器人完成、模拟晾干均写入 `events`，并经正常摄取链路写入 `life_memories`。一次状态变化只写一次；机器洗完不会写成已经晾衣。

数据库当前状态新增 `housework_plans`、`housework_steps`、`household_machines`、`laundry_batches`。人工作业按活跃心跳推进，中断或超过 90 秒的未观测间隔不补算；机器计时及已经开始的晾晒会继续，重启后按保存的截止时间结算。剩余粗计划时间不足时保留步骤，在后续匹配或泛家务时段继续。

手机已有 event 时间线直接显示新事件，无需新增页面。生活状态和聊天上下文包含机器与衣物状态，避免把“洗好了”误说成“收好了”。

## 跨粗计划的后续任务

`household_followups` 保存每批衣物的晾晒、收衣依赖任务。洗衣启动时建立等待洗完的任务；机器洗完后变为 ready；实际晾晒完成后前一任务完成，并创建等待晾干的收衣任务。队列根据已提交衣物状态恢复，重启和跨日不丢失。

`household_followups.schedule_ready` 每个可调度周期检查当前时段。只借用可暂停的居家 free/resting 时段，避开工作、睡眠、外出、护理、餐食、用户预约及待处理改期消息。阅读和电影至少连续进行 5 分钟后才允许暂停。时间预算包括实际配置路径、操作、返回原房间和 180 秒执行缓冲，并保留原活动续接窗口；时段不够则等后续可用时段，不强行插入。

插入会形成新的粗计划版本，保留已过去的部分和其他未来安排。正在阅读或观影时以正式中断事件结算进度，将同一资源的细计划复制到返回后的续接时段，不重新调用模型选书选片。洗衣任务完成不表示原活动完成。未来日程被用户或世界更新改动时，以最新日程为准，尚未完成的后续任务仍在队列；用户明确取消的当日后续安排不自动恢复。

这些是宿主调度规则，不生成假的家务完成事件。实际晾晒、收衣仍通过既有 housework 步骤执行并写 event。若始终没有可用时段，任务会保留待办，不承诺一定在某个截止时间内完成。
