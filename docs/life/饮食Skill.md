# 饮食 Skill

粗计划进入 eating 时由饮食 Skill 生成细计划。在家只允许自己做或点外卖；律所固定默认带饭，先加热再吃，不补写做饭和打包经历；餐馆保留粗计划指定地点，根据店名推断适合的菜式。不允许细计划另选餐馆，不声称拿到了真实菜单。

左然不吃辣，擅长做饭和甜品。选菜时读取用户当前饮食偏好，参考喜欢的食物、忌口或过敏、口味和其他备注；未填写时保持未知，不虚构用户习惯或两人正在一起吃饭。

用户在手机「个性化设置 → 我的饮食偏好」编辑。服务端通过 `/personalization/settings` 保存到应用设置 `user_diet_preferences`，每次新用餐计划经统一工具 `diet.preferences` 读取。旧版客户端未提交此字段时保留已有设置；明确提交空对象可清空。工具 `meals.prepare` 负责生成并持久化本次选择。

做菜、等待外卖或等待上餐属于准备阶段，不会立即算作吃完。在家做菜后需要端到餐桌，再开始吃。进度按实际活动心跳累计；暂停、离线和恢复间隔不计入。吃完才产生可用于饥饿等状态更新的完成事实，并保留生活事件和记忆。

餐饮地点从 `libra/world/schedule_rules.json` 的 restaurants、breakfast_shops 接入运行时，其源清单为 `docs/character/左然城市地点清单.md`。连接道路耗时是生活模拟估算，不是地图实测。安装地点时保留原位置和活动，不会瞬移。外卖和点餐均为生活模拟，不会向真实商家下单。

计划和阶段进度保存在生活数据库当前状态的 `meal_plans`、`meals`、活动记录中；重启后恢复，已生成的同次计划不会反复调用模型。
