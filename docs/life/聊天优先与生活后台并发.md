# 聊天优先与生活后台并发（2026-09-26）

此前 `LocalLifeApp.tick` 在整个后台周期持有适配器锁，包括多轮模型等待；
`accept_message` 也需要这把锁。生活模型与聊天再竞争同一个普通模型锁，
导致消息在接收前、生成前都可能排队。

修复实现：

- `application/model_lane.py` 提供模型通道。用户请求从进入 `_chat_impl` 起登记前台优先，
  直到回复流程结束。已运行的调用正常结束，后续后台调用等待用户聊天完成；
  不强杀共享聊天线程，也不并行写入它。聊天辅助任务通过 `copy_context` 继承优先级。
- `LocalLifeApp.model_wait` 在生活模型等待模型通道/返回期间释放适配器状态锁，
  允许用户消息提交。独立 `_tick_lock` 保证只有一个调度周期，关闭时也等待该周期退出。
  数据库事务保持原样；模型返回后重新取得状态锁，并检查输入版本。
- 发生输入版本冲突的生活决策标为 superseded，保留审计，重新读取最新状态决策。
  不提交旧行动，不把用户正常打断累计成三次模型失败。被打断的阅读/工作检查点在尚无暂存结果时
  也会撤销；已有暂存结果仍走原审核流程，不能绕过。观察同步保留已吸收事实，余下内容重新处理。
- 用户聊天期间不启动新的生活周期；已经开始的周期在可让出的边界暂停后续推进。

日志输出 `[libra] chat_timing`，不包含消息内容：
`chat_queue_seconds` 为聊天队列等待，`life_input_seconds` 为生活消息接收耗时，
`model_lane_wait_seconds` 为模型通道等待，`model_lane_hold_seconds` 为持有通道时间，
`reply_model_seconds` 为回复模型调用耗时，`total_seconds` 为服务器整个聊天处理时间。
这些指标部分包含或重叠，不能直接相加。
