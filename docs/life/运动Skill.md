# 运动 Skill

粗计划确定时间和地点，exercise.prepare 通过统一工具层保存运动会话，不调用模型生成训练内容。

- 在家：仅客厅清单中的跑步机。开始事件“左然开始跑步”；结束事件“左然结束跑步，完成运动打卡”。
- 健身房：到达并开始时记录“左然到达健身房，开始健身”；实际开始离开时记录“左然结束健身，离开健身房，完成运动打卡”。不细分动作或器械。
- 游泳馆：“左然开始游泳”／“左然结束游泳”；射击馆：“左然开始射击”／“左然结束射击”。仅开始结束事件，不生成训练内容或成绩；沿用运动会话和打卡存储，时段结束或提前离开时结束。
- gym、swimming、shooting 地点均来自 schedule_rules.json，并接入可执行移动路径。
- 健身房从 schedule_rules.json 的 gym 清单接入可执行地点，沿用城市通行连接的模拟时间，不代表真实地图距离。
- 时长只累计实际在线活动的心跳，中断和恢复保留进度，离线不补算。家中跑步在时段结束或实际离开时结束，健身房时段结束但未离开时不提前打卡。
- 没有实际执行或零时长不打卡；同一会话 ID 只保存一次。

数据库 life_state.current 的 exercise_sessions 保存会话，exercise_checkins 保存日期、地点、模式、起止时间、active_seconds。生活状态 API 与聊天上下文同时提供这些字段。事件进入 events 和生活记忆。

其他运动场所暂不套用健身房规则；地点缺少可用跑步机时明确阻塞，不移动到未经粗计划指定的房间。
