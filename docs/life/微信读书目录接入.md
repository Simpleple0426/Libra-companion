# 微信读书目录接入

使用腾讯官方 WeChatReading 1.0.4 文档中的 Agent Gateway，通过项目统一工具层提供 weread.search、weread.info、weread.chapters。无需额外部署 Cloudflare Worker。

## 凭据

从 https://weread.qq.com/r/weread-skills 登录获取 API Key，保存到 config/secrets/weread-api-key.txt，只写 Key 本身。也支持 WEREAD_API_KEY 环境变量，环境变量优先。每次读取配置，填好后无需重启。

工具日志、模型输入及状态 API 不保存 Key。鉴权 Header 仅发往固定官方 HTTPS 地址，拒绝重定向。只允许搜索、书籍信息、章节目录三个接口，不读取账号阅读进度，不写书架，不获取正文。

## 流程

书房候选合并本地导入、libra/reading_knowledge/catalog.json 原有书单和书店购书。原有书单以 catalog:<book_id> 独立任务自动获取目录，不伪造购买记录或购买事件，不使用 excluded 项。书单按作品匹配书名（含 alternate_titles）和作者，多个一致版本可选搜索结果中的首个版本并缓存；实际购书仍要求唯一版本匹配。无法确认的作品继续等待重试，不凭空生成目录。只有目录就绪才进入阅读候选；同名本地导入优先、合并书库去重。reading_status=read 保留为人设背景，不初始化或覆盖模拟阅读进度。

书店自主选书在配置 Key 后优先直接搜索微信读书，购书和介绍流程沿用原有规则。未配置时保留豆瓣选书。购买的书先保存，再由后台获取目录；已有豆瓣购书记录也会自动尝试匹配微信读书版本。使用 ISBN，或书名与作者的一致且唯一匹配，不确定时保留待重试，不猜测。

life_weread_library 保存每本已拥有书籍的任务、目录缓存和状态。网络工作独立线程执行，不阻塞生活心跳；获取成功后由资源同步加入书房阅读候选（通常下一次资源同步，最长约五分钟）。失败重试，缺 Key 时等待配置。已缓存目录可离线使用。

章节 ID、顺序、标题、层级和字数转换为现有 structure_simulation 结构，不要求本地 EPUB 或正文文件。缺少有效字数的章节以4000模拟单位估算，标记 length_basis；计时与百分比是模拟进度，不代表理解正文。读书进度保存在左然自己的 life_state.current，不读取或写入用户微信读书进度。

原本本地书库继续有效，同名已导入书优先保留本地版本。当前缓存不主动自动刷新，避免章节版本变化导致阅读坐标漂移。

## 验证

在 backend 执行 `python -m scripts.check_weread`，只读验证搜书、详情和目录，输出标题、章节数量等摘要，不修改生活书库。

接口依据：https://github.com/Tencent/WeChatReading ，https://cdn.weread.qq.com/skills/weread-skills.zip 。官方要求升级时停止使用该响应，状态记录 weread_upgrade_required。
