# Skill 日程调度

当前唯一生成链路：DailyAgenda → skill_agenda → skill_router → 对应 Skill。

粗计划只安排时间、状态、地点、宽泛意图，不选书、不选电影、不写菜名、不生成工作成果或未来事件。读取 schedule_rules.json 中的粗时间窗口与地点池；地点依据家庭、律所及城市空间清单，只使用实际可达地点，通行时间按运行世界路径预留。工作日由已有工作日历决定。

十类执行器：阅读、电影、饮食、个人护理、家务、运动、电视、休息、外出、工作。前两者使用结构或片长与本地进度选具体资源；其他 Skill 按当前粗计划准备各自细计划。律所内工作、在家做饭、跨房间家务可在粗时段内部移动。未来安排只有实际开始执行才产生事件。

用户约定是独立的预留时段：`activity=user_time` 不路由到上述 Skill，不要求地点或移动，也不生成细计划。粗计划保留“陪用户逛漫展”等具体标题；进入时段后记录一次 `user_time_start` 动态。地点保持未知，内部上次已知位置不因预约被改写。其余生活活动继续按原地点与 Skill 规则执行。

每天夜间保留洗澡与睡前洗漱机会，卧室意图是准备睡觉，睡眠仍只由晚安机制触发。已完成的当日洗澡与餐食不重复安排。家中用餐由饮食 Skill 选做饭或外卖，律所用餐默认带饭，餐馆沿用粗计划指定地点。粗计划不再单独安排备餐和工作中的短休。

旧 Builder、legacy_agenda、schedule_store、apply_rule_schedule 与设备派生日程规则已删除。原有实际移动与活动结果的审计读取基础设施仍使用，它们不生成旧日程。

迁移：停服后运行 `python -m scripts.retire_schedule_data --apply`，通过调度器锁保护并备份数据库。清除旧预生成状态、动态、属性快照及派生投影，清除旧粗细计划缓存；保留日程修订序号和用户约定，重建新粗计划。实际 Skill 事件、生活记忆、阅读/观影进度、购书记录、摘录、影评、用户消息均保留。旧状态读取接口保留空表兼容，但旧写入器与属性预生成算法已经移除；备份导入不再恢复旧日程表和生成标记。
