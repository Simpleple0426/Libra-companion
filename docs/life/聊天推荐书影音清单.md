# 聊天推荐书影音清单

用户普通聊天消息进入生活系统时，同一事务写入 `life_media_messages` 待处理队列。后台调用 `media_mentions` LLM 阶段提取具体书籍/电影及逐字消息依据，普通提及为 `mention`，明确叫左然读/看为 `request`。否定推荐、假设举例及无法辨别的作品不新增。这个过程不直接改变日程，也不生成购买、阅读或观影完成事件。

`life_media_recommendations` 保存在 `data/life/local-life-v1/prototype.sqlite3`，记录作品、推荐优先级、来源消息、处理状态及资源 ID。重复作品合并来源；明确推荐提升优先级。先匹配现有可用资源，新书通过已有微信读书统一工具读取资料与目录，新电影通过豆瓣统一工具核对身份和片长。网络失败重试三次后保留为 `needs_review`，同名无法唯一确认时为 `needs_clarification`，这些状态不会冒充可执行资源，也尚不自动发出追问。

目录写入现有 `life_weread_library` 缓存，电影写入现有 `discovered_movie` 资源，再由资源同步进入阅读/电影候选。聊天推荐不写入书店购买表。选取候选时提供推荐来源，明确请求优先考虑；已有完成进度不会因推荐而清空。电影已经看完时，不再仅凭该推荐提升重看优先级。

生活状态接口和聊天验证上下文包含 `media_recommendations`。异步处理可能晚于当轮聊天回复；只在出现清单回执后才能称已保存，`ready` 才表示资源已核对。当前不会回扫上线前的聊天记录，不新增 App 清单页面。
