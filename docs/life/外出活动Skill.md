# 外出活动 Skill

通过统一工具 outing.prepare 和 outing 活动，按地点类型生成宽泛的开始结束事件。生活调度负责地点和移动；饮食、运动、阅读等明确意图优先使用已有 Skill。

地点从 schedule_rules.json 分类接入可执行通路。书店、商场/超市、步道、展馆、娱乐场所、办事场所有不同事件描述；未分类地点使用普通外出事件。未凭空向城市清单添加公园等地点。

## 书店

已安装豆瓣 MCP 的 books.search/books.detail 通过统一工具层进行只读检索。后台用人设和用户记忆选择搜索词、候选书籍、再以左然口吻生成简短介绍；简介依据来源资料改写，不能装作已读。
更新：配置微信读书 API Key 后，优先直接使用 weread.search/weread.info 搜书选书；未配置时沿用豆瓣。购买后自动获取微信读书目录，资源同步后可阅读，不必手工导入文件。详见《微信读书目录接入.md》。

每次实际到访最多购买一本。去重覆盖配置书库、私有阅读库 manifest 元数据和历史购买记录；比较豆瓣 ID、ISBN、规范化标题及版本/副标题，模型同时检查候选和已拥有书的译名关系。名称完全不同且没有共同标识的译本仍受上游元数据准确性限制。

保存前在同一数据库事务内重新检查仍在该次书店活动、未过时段、未买过和书库去重。购买事件、拥有记录和介绍草稿一起提交。日程改版但未离开场所沿用同一 visit_id；真实开始移动才结束本次到访，避免变更粗计划 ID 后重复购买。

无合适候选就跳过购买。网络/模型失败有有限重试；离开书店后的迟到结果不能形成购买。新书只成为已拥有条目，未自动进入可读资源；有结构的导入仍走原有阅读库流程。

## 散步

每次到访最多一条面向用户的想法，结合地点、开始时间、人设和真实用户记忆。不假定用户同行、未发送的话不写成已发送，没有现场数据时不声称观察到了夕阳或天气。可以写想与用户分享或未来一起体验的愿望。

## 存储与调度

- life_state.current.outing_sessions：外出会话及地点类型；outing_visit：未离开的当前到访。
- life_outing_jobs：后台任务、保存的生成阶段、重试状态；独立线程运行，不阻塞生活心跳。重启后可从持久化阶段继续。
- life_owned_books：模拟购书元数据，visit_id 和作品键唯一。
- life_dynamic_drafts：正文、关联事件、地点、作品资料、来源链接、生成时间；状态 pending_display，published_at 为空。按 visit_id + kind 唯一。
- events / life_memories：实际执行的外出和购书事件；尚未展示的草稿不当作已发送消息写入记忆。

生活状态 API 提供 dynamic_drafts（最近50条）及 owned_books，方便以后动态区接入。本次没有发布或发送动态，也没有真实电商购买。
