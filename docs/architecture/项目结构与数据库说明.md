## 1. 项目总览

Libra Companion 是一个以本地数据为中心的 Android 私人陪伴应用：Flutter 客户端负责界面和设备能力，Windows 上的 FastAPI 后端负责聊天、角色认知、记忆、情绪、生活模拟和第三方服务协调，模型通过本地 CLI 或可选服务调用。

```text
Android / Flutter
    ↓ HTTP、上传、轮询和推送
FastAPI main.py
    ├─ 回合路由与认知流水线
    ├─ 人设、情绪、记忆与知识召回
    ├─ 日历、待办、书房、影音、小红书、天气
    └─ SQLite: backend/libra.db
         ├─ 业务事实与用户内容
         ├─ 记忆证据、索引和审计
         └─ 回合、模型用量及后台任务记录
```

依赖方向约定为：`main/app → application → domains → infrastructure`。领域模块不应反向导入 `main.py` 或 HTTP 层。

## 3. 后端文件

### 3.1 当前后端目录

```text
backend/
├─ main.py                    # 稳定 ASGI 兼容入口
├─ app/runtime.py             # 当前组合根与待继续拆分的运行时
├─ app/api/                   # HTTP 请求模型和路由
├─ application/               # 跨领域用例编排
├─ domains/
│  ├─ memory/                 # 个人记忆及其 schema
│  ├─ affect/                 # 情绪、评价和 Need
│  ├─ world/                  # 当前上下文与生活模拟
│  ├─ content/                # 阅读、影视和小红书
│  └─ persona/                # 人设证据、提示词和共同历史
├─ infrastructure/
│  ├─ sqlite/                 # SQLite 实现
│  ├─ embeddings/             # 本地向量适配器
│  ├─ models/                 # 模型 CLI 适配器
│  └─ weather/                # 天气适配器
├─ scripts/                   # 回填、导入、诊断和维护命令
├─ config/ prompts/ persona/  # 运行配置与文本资源
├─ life_prototype/            # 当前生活引擎
├─ vendor/                    # 第三方工具
└─ uploads/ backups/          # 私人运行数据
```

原来位于 `backend/*.py` 的扁平领域模块和重复维护启动器已移除。根目录保留 `main.py` ASGI 入口；维护命令从 `backend/` 执行 `python -m scripts.<模块名>`，私人数据导入导出实现位于 `application/private_data.py`。

#### 四阶段重构状态

1. **应用层**：`main.py` 已缩为稳定 ASGI 入口，原运行时进入 `app/runtime.py`；HTTP 请求模型和记忆管理 router 已进入 `app/api/`。runtime 是当前组合根，后续路由剥离必须通过显式依赖对象完成，不能复制全局状态。
2. **应用编排与记忆拆分**：统一召回和 turn routing/pipeline/actions 已进入 `application/`；原 1281 行 `MemoryStore` 已按公共模型、持久化、写入分段、提取任务、召回和管理拆开，`store.py` 与 `core.py` 只负责组合。
3. **领域层**：memory、affect、world、content、persona 已按业务边界归入 `domains/`，领域 schema 与实现放在一起。
4. **基础设施与工具层**：SQLite、embedding、模型 CLI、天气进入 `infrastructure/`；回填、导入、benchmark、trace 等进入 `scripts/`。

`libra.db`、上传文件和备份仍保留原位置，以避免在运行中的 WAL 数据库及手机媒体上做破坏性搬迁。路径已集中到 `infrastructure/paths.py`；停服并完整备份后，可设置 `LIBRA_RUNTIME_DIR` 指向独立 `runtime/`。数据库、上传、备份、私有书库、房间媒体和 secrets 会共同切换，不能只移动其中一个目录。

### 3.3 回合认知与回复链路

| 文件 | 职责 |
|---|---|
| `application/turn_routing.py` | 为所有用户消息与附件返回统一处理契约，启用召回与完整情绪评估；自身不调用模型、不写情绪状态，也不裁决工具权限。 |
| `application/turn_pipeline.py` | 统一回合计划、校验、交付和原子提交边界，失败时保持关闭状态。 |
| `application/turn_pipeline.sql` | cognition 回合、上下文版本、反馈、交付、通知和后处理任务表。 |
| `application/turn_actions.py` | 模型可请求的少量显式本地写操作；不接受任意 SQL。 |
| `domains/memory/cognition.py` | 当前事件优先的 appraisal、回复策略、规则校验、润色和使用反馈。 |
| `domains/world/current_context.py` | 构建带来源、置信度和过期时间的“当前上下文”，并向不同消费者投影。 |
| `app/api/trace.py`、`trace_console.html` | 浏览器 Trace 控制台，展示 cognition turn、上下文、计划、证据、工具、校验和投递结果。 |

典型聊天链路：

```text
用户输入 → route_turn
        → Current Context / Memory Retrieval / Appraisal
        → Response Plan
        → 模型生成
        → 规则校验与可选润色
        → 消息、认知回合、反馈原子提交
        → 后处理记忆与通知
```


## 6. `libra.db` 表说明

当前 schema 共包含 **88 个业务、派生或虚拟索引表**，另有 **20 个由 FTS5 自动维护的影子表**。下面覆盖全部 88 个需要开发者理解的表；影子表按规则统一说明，不逐个展开。

### 6.1 表的安全分类

- **业务真相表**：聊天、待办、信件、原始经验、记忆正文等，不能通过“重建索引”恢复。
- **派生/索引表**：FTS、embedding、calendar summary、attribute snapshot 等，可从源表或源文件重建，但重建程序必须匹配当前版本。
- **审计/流水表**：recall log、usage event、cognition turn、job 等，主要用于可解释性、幂等和故障恢复。
- **FTS5 影子表**：SQLite 自动创建的 `*_fts_data`、`*_fts_idx`、`*_fts_content`、`*_fts_docsize`、`*_fts_config`。不要直接查询或修改；只操作对应的 `*_fts` 虚拟表。

## 7. Schema 来源和初始化关系

数据库不是由单个 SQL 文件完整定义，而是启动时由多个模块做幂等初始化和增量迁移：

| Schema 来源 | 主要负责 |
|---|---|
| `infrastructure/sqlite/database.py` | 连接、schema 初始化与兼容导出；聊天内容读写已下沉到 repository。 |
| `infrastructure/sqlite/content_repository.py` | 会话、消息、共享记忆和信件相关表。 |
| `domains/memory/memory_schema.sql` | Episode 记忆主链、证据、索引和召回审计。 |
| `domains/memory/memory_evolution.sql` | Semantic/Story/Relationship/Self/Reflection 和依赖关系。 |
| `domains/affect/emotion_v1.sql` | affect 状态、事件、prospect、observation。 |
| `application/turn_pipeline.sql` | cognition 回合、上下文版本、交付、反馈和后处理。 |
| 各模块 `initialize()` / migration | 后续新增列、索引及领域专用表。 |

因此修改数据库时应遵循：

1. 在所属领域的 schema 或迁移函数中做幂等变更；
2. 同时更新测试和本文档；
3. 不直接把本机 `libra.db` 当作 schema 模板；
4. 大规模写入前先用在线 backup 创建可验证备份；
5. FTS/向量表只作为派生索引，模型、维度、内容 hash 或 revision 变化时重建；
6. 不直接操作 FTS5 影子表，不手工删除 WAL/SHM 文件来“修复”数据库。
