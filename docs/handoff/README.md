# 桌面端讨论 → VS Code 实现

这里存放需求讨论形成的交接内容。桌面版 Codex 负责梳理需求、讨论方案和整理交接；VS Code 中的 Codex 负责检查代码、实现和验证。

## 使用方式

1. 在桌面端讨论需求，形成方案后，复制 `TASK_TEMPLATE.md` 为 `YYYY-MM-DD-01-简短任务名.md`，填写交接内容。
2. 在 `INDEX.md` 登记任务、状态和文件链接。每个任务单独保存，后续讨论更新原任务，并记录重要变更。
3. 在 VS Code 打开同一个项目，将下面的提示词复制给 Codex，并替换任务文件名。
4. VS Code 完成实现后，在同一任务文件的“实现反馈”中记录结果，并更新索引状态。
5. 后续桌面端讨论先读取任务文件和实现反馈，再继续调整方案。

## 给 VS Code Codex 的提示词

```text
请读取 docs/handoff/README.md 和 docs/handoff/【任务文件名】。
根据任务文件中已确认的需求和验收标准，在当前项目中完成实现。
先检查适用的 AGENTS.md、相关代码和工作区现有改动；保护已有工作。
区分已确认需求、建议方案和待确认问题，以实际代码为依据验证方案。
若遇到影响需求含义的缺失信息，提出具体问题；其余可独立完成的工作继续推进。
执行与本次变更相关的验证，将修改内容、验证结果及未解决问题写回任务文件的“实现反馈”，并更新 docs/handoff/INDEX.md。
```

## 协作约定

- 交接文件是两端共享的上下文；不要假设另一端已经读过聊天记录。
- “讨论中”的任务用于讨论；用户要求开始实现后，标记为“待实现”。
- 状态流转：讨论中 → 待实现 → 实现中 → 待验收 → 已完成；受阻时写明原因。
- 需求变更写入“变更记录”，避免覆盖后无法判断最新决定。
- 方案中没有验证过的代码位置、接口或假设必须明确标记，不将推测当作项目事实。
- 不在交接文件中写入密钥、令牌、私人聊天原文等敏感信息。
