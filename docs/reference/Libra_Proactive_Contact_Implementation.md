# 主动联系统一决策（旧候选队列方案，已退役）

> 2026-09-06：本文所述候选队列、30 秒聚合及 `proactive_contact_v1` 已从运行时移除。现行实现以 `Libra_UnifiedEvent_V1_规格.md` 为准：每个主动触发直接形成 UnifiedEvent，进入与用户消息共同的认知回合，由 Response Plan 在生成前决定是否打扰。本文仅保留为历史设计记录。

## 范围

聊天类九个生成入口先入候选队列：日常检查、需要冲动、左然生活状态、用户状态、用户动态、天气、习惯、待办、小红书分享。前端不变；信件、动态发布不纳入此队列。

候选保存于现有 SQLite 的 app_settings，键 proactive_contact_v1。没有新增数据库表；已有设置备份可携带队列。历史原文、记忆和情绪数据不清理。

## 链路

原触发器观察/评估 → 候选入队 → 30 秒后台轮询 → 当前可用性与跨来源间隔筛选 → 选择最多两个具体缘由 → 新鲜上下文与记忆召回 → 模型决定开口或沉默 → 公共校验与发送前再检查 → 共同原子提交与通知。

- 同来源候选以最新内容替换旧内容；短暂收集窗口允许相邻触发器一起参与选择。
- 具体事件优先于泛泛想联系；最多围绕一个主要缘由表达，第二个仅在相关时合并。
- 忙碌、勿扰、睡眠、最近五分钟聊天时延后；关闭总开关清空积压。
- 各类候选有 10 分钟至 2 小时有效期，到期丢弃；不在恢复联系后逐条补发。
- 跨来源发送间隔按主动程度 1～5 为 90/60/40/30/20 分钟；这是上限约束，不是发消息时间表。明确待办/习惯候选也不能绕过勿扰或公共间隔；目前不是精确时间闹钟。
- 未发送的评估至少间隔五分钟；未回复不会提高优先级。没有话题不以拍一拍填补沉默。
- 候选领取后先消费再调用模型。失败、进程中断可能失去这次机会，但不会恢复后反复重发旧主动消息。

## 边界与待验收项

这是统一候选选择与发送预算，不是完整的未来事项调度器。可从召回中使用已有证据的未完成事项，但没有新增自动从聊天提取未来跟进日期的功能。原触发检查频率仍保留，仅不再直接生成聊天消息。

原分支中的天气观察基线、待办检查标记等表示已检查/提交候选，不应解释为最终发送；实际输出以 cognition_delivery 和消息记录为准。小红书卡片在最终保存后记录分享标记。

队列操作由单进程锁保护，适用于当前单后端部署，不支持多 worker 并发调度。队列收尾与消息原子提交是两个事务：崩溃边界不保证精确一次；正常回合保留共同提交与发送前状态检查。

本轮只修改代码和隔离测试，不重启后端，不调用真实模型，不修改真实数据库。真实模型与手机端的自然程度、重复频率仍需联调。

## 位置更新与报备（后续改造）

- 生活状态变化仍记录 affect 事件与状态观察，但不再把位置变化直接作为联系理由。
- 文本聊天及该聊天入口已有的语音原文支持保守的明确指令，如“到了告诉我”“到了跟我说一声”。仅绑定当时正在进行、具有明确终点和结束时间的 commuting 行程。不猜测未来行程、引语、假设或目的地别名；无可绑定行程时提示澄清。独立电话入口尚未接入此指令登记。
- 到达依据是项目自身生活状态从该行程切换到终点位置，属于角色生活模型，不是现实 GPS 定位。不同地点、不同旅程不触发。
- 报备候选含 reason、event_ref、evidence_refs、topic_key、arrival_state_id 和 facts。普通无结构化依据的旧位置候选被丢弃。
- 一次请求至多产生一次候选；取消报备清除待处理请求与授权，发送前重新核对授权和当前状态。仍尊重统一冷却、过期、勿扰，因此是尽力联系而非保证送达的提醒任务。
- 统一生成入口将召回的角色证据经 format_evidence 显式加入提示词；候选和报备约束同时进入计划及校验上下文。
- 程序拦截无依据的常见到达报备句式；语义校验覆盖换句式报备、重复表达和虚构场景细节。不是用正则判断所有事实；语义效果依赖实际模型，需要真实联调。
- 新语料未在本轮填充；空语料时仍执行程序规则与计划约束。报备登记随 app_settings 备份，不新增表、不清理用户数据。
