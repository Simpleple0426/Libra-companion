# Memory Phase A–C 首版实现（历史归档）

本文件仅保留 A–C 首批实现时的历史快照，不代表当前状态。其中 V2、55 项测试、仅记录 context_selected 等描述已被后续实现更新。当前行为以 [记忆系统实现与验收记录](../Libra_Memory_Implementation.md) 为准；本归档不再同步维护。

## 运行行为

- 后端启动时在现有 SQLite 数据库创建新表，固定原主聊天线程 ID。旧长期记忆表保留但聊天和信件不再读取，也不迁移旧记忆。
- 初始化之后保存的 chat/text 消息与 RawExperience 在同一事务中提交。历史消息不回填；原 Codex 线程仍继续恢复使用。
- 每 15 秒扫描待处理原始经历。片段以线程、显式换话题、词汇连续性、时间间隔和长度分段；闲置 2 分钟关闭，最多 16 条消息，20 分钟间隔形成边界。一条消息中的多个事件可形成多条 Episode，共用原始证据。
- 后台模型先给出写入建议，再通过单独会话进行事实核验。服务检查来源、原文引用、说话人、类型、数值、事件身份和目标版本，随后将 Episode、Source、Revision、生命周期初始化、检索索引和任务结果一起提交。
- 后台模型会话不修改主线程号，不占用主聊天锁。每次 CLI 调用超时 60 秒；任务租约 10 分钟，失败指数退避，5 次后标记 failed，可手动重试。重启后从持久化队列继续，不依赖旧消息游标。
- 明确纠正不能被静默忽略；纠正未处理完成时，对相关旧 Episode 保守停止注入。
- SQLite FTS5 使用应用层中文单字/二元片段、英文与数字 token，结合实体和受限时间查询。检索回表核验版本、有效性、敏感性、原始来源，执行当前消息与近期上下文去重，最多返回 4 条。
- Packet 默认采用 2200 字符的硬预算，包含来源、报告时间、置信度及不确定性标签。当前实现不是模型 tokenizer 的精确 token 预算；输出转义也计入字符预算。
- 仅记录 `context_selected`，不宣称模型实际使用了每条注入记忆，也不自动强化。失效记录和审计仍保留。
- 原线程恢复失败、空回复重试、称呼修改、人格刷新与私人数据导入均不会自动新开主线程。主线程仍依赖原 Codex 会话存储。

## 检索与可选向量接口

默认不调用 embedding 服务。`MemoryStore(path, embedding_adapter=...)` 可接入实现 `model_id`、`dimensions` 和 `embed(text, timeout_seconds=...)` 的提供方；提供方必须遵守超时。后台 `refresh_embeddings()` 按记忆 revision 更新向量缓存，模型、维度、预处理版本不符时不能混用。向量不可用仍运行 FTS5/结构化检索。

本地文本索引与 Episode 使用同一事务提交，替代设计中通用的异步索引任务；这利用 SQLite 本地索引特性，避免文本索引半更新。可选 embedding 在事务外计算、提交时重新核对 revision。FTS5 缺失会记录降级；索引可从 Episode 重建。

RawExperience 的 `ingest()` 也支持 unified_event/state_snapshot，但当前自动接线仅包含文本聊天；多模态及世界状态生产者需要后续适配。当前分段为有界启发式与模型多事件拆分，不声称已实现设计中全部连续性评分项。结构化 affect/commitments 字段预留，首版主要将报告的情绪和计划保留在带证据的 Episode 内容中。

## 查看与纠错

| 接口 | 用途 |
|---|---|
| `GET /memory/status` | 查看检索能力、记忆摘要、任务状态和错误代码 |
| `GET /memory/records/{memory_id}` | 查看内容、来源和版本历史 |
| `POST /memory/jobs/{job_id}/retry` | 重试 failed 任务 |
| `POST /memory/records/{memory_id}/invalidate` | 将指定记忆标记失效，保留审计 |

私人数据 ZIP 格式升级到 V2，包含新记忆、证据、版本和任务。仍可导入 V1；V1 没有新记忆数据，因此导入该快照后新记忆为空。主线程指针和 embedding/FTS 缓存不进入 ZIP，导入保留本机主线程并重建文本索引。整个数据库的原有备份也覆盖新表。

## 验证方式与边界

在仓库根目录执行：

```powershell
python -m unittest discover -s backend -p 'test_*.py'
python backend/benchmark_memory.py --size 10000 --queries 100
```

`backend/fixtures/memory_v1_cases.json` 保存 60 组人工设计案例（40 development、20 heldout），覆盖相关召回、中文短实体/英文项目、闲聊、无关查询、纠正和 thread 去重。另有混合 20 个事件的检索测试，及事务失败、租约接管、原文校验、核验拒绝、版本隔离、索引恢复、备份兼容和主线程连续性测试。

这些自动化测试使用临时数据库和受控模型返回，验证工程行为；不代表真实模型已经达到设计中的语义抽取、无证据事实或复杂同名事件消歧指标。模型事实核验是额外检查，不构成事实正确性的绝对保证。真实模型的离线回放与长期对话观察仍是后续质量验证项。

本次结果：55 项后端测试通过，其中包含 60 组检索夹具和 20 事件混合检索检查。一万条模拟 Episode、5 次预热后执行 100 次查询，本机 Windows/Python 3.13.9/SQLite 3.51.0 下 median 21.52 ms、p95 24.24 ms，目标项目命中 100/100；包含本地查询、Packet 构建与日志落库，不含远端模型耗时。

本次开发没有重启正在运行的后端，也没有删除真实聊天、旧记忆、相册或会话文件。代码在后端下次启动时生效。
