## 保留与替换

- 保留已重构的 A–I 记忆系统、原始经历、记忆后台任务、固定会话线程及会话存储。情绪系统消费记忆证据，不替代记忆系统。
- 保留生活安排、身体疲劳来源和手动用户状态；新情绪状态独立初始化，不迁移旧情绪数值。
- 用户随后授权彻底清理旧版：旧记忆、旧情绪和旧语料表及其 CRUD / 建表 / 检索代码已删除；主库和已有历史数据库备份均已清理，旧语料目录的 22 个文件已删除。新系统、聊天原文、相册日记和会话存储保留。
- 新语料目录为 `libra/zuoran_corpus_v2`，目前没有已审核样本。稳定人格提示仍保留，不凭空生成原作证据。

## 后端链路

UnifiedEvent → 持久化事件任务 → CurrentContext / 记忆 / 审核语料 → Appraisal → 程序计算 Emotion → Mood / Need → 表达上下文。

`emotion_contracts.py` 管理事件与严格模型输出契约，`current_context.py` 构建来源可追溯的快照，`affect_engine.py` 计算数值，`affect_service.py` 负责事务、租约、重试及查询，`corpus_v2.py` 负责新语料校验和检索。参数与模型提示位于 `backend/config`。

已接入文本聊天、语音转写、电话回合、实际助手回复、生活变化、用户手动状态、天气、用户时间线、内容发现、待办与打卡、定时探测及身体疲劳变化。聊天保存与用户事件同事务；待办和打卡完成使用事务 outbox。其他主动来源通过已有业务触发器接入，不宣称所有外部状态变化都已实现事务投递。

事件 ID 幂等，同一事件不能更换正文。单写者租约避免并发重复计算，状态与处理收据原子提交；自动尝试最多三次，失败后可显式重试。模型失败不提交半份情绪状态，实际用户到达仍计入互动间隔。

定时探测、内部状态变化不调用模型制造情绪；助手实际回复可更新 Need，但不再次生成情绪。超过 24 小时的积压事件保留收据，不补发当下情绪和 Need 变化。

## 数值与语义边界

- 18 类 OCC 情绪，8 项 Core Goal；Active Goal 权重继承 Core，不由模型给最终分数。阈值、保持期、半衰期、同类聚合及同事件复合由程序计算。
- PAD 初值为 `(0.2, -0.15, 0.45)`；六项 Need 使用配置中的明确初值。Need 表示待满足需求，不是亲密度，也不是要求用户配合的理由。
- Mood 与 Need 基线回归采用指数松弛，Mood 按全局分钟区间演进。这是对规格中按调用步长线性更新公式的工程调整，避免查询频率改变状态；GET 不持久化衰减结果。
- Prospect 独立于记忆的未完成事项。匹配需要明确结果、候选 ID 和当前事件原文；模型仍可能误判，需要真实样本验收，不能将同类型考试天然视为同一事项。

## CurrentContext

采用 `Libra_Current_Context_V1_规格.md` 的结构与 ObservedValue。过期信息转 unknown；未知不等于空闲。手动状态保留标签，但推导活动和可用性受有效期约束。通勤目的地不视为已经到达。

用户即时状态自动提取目前仅覆盖少量明确当前陈述，不做全面模型抽取。地点使用受控别名；缺失的关系、任务焦点及工作日等证据保持 unknown/null。互动计数来自最近最多 500 条消息，不是无限历史统计。Need 投影去掉互动间隔并标注程序已经施加压力，防止模型重复加分。

## 语料与表达

仅 `approved` 且非 `runtime_generated` 的 V2 条目进入检索，必须具备来源定位。保留 context、character_logic、preferred_direction、avoid_direction、置信度等信息，作为人物表达证据，不当作本项目实际共同经历。回复校验增加角色证据和近期助手回复去重。

导入工具是 `backend/import_canon_corpus.py`，必须显式指定 `--database`；导入仅替换 V2 索引，不读取旧格式。尚未制作真实语料或验收检索质量。

## 接口、备份与验收

- `GET /emotion/v1/state`：当前完整状态。
- `GET /emotion/v1/context`：当前上下文快照。
- `GET /emotion/v1/events/{event_id}`：事件、模型输出与收据。
- `POST /emotion/v1/events/{event_id}/retry`：重试失败事件。
- 旧情绪查询接口保留轻量兼容，但不伪造旧亲密度等分数；旧前端尚不能正确展示全部新字段。

私有备份格式现为 V5，包含新情绪状态、事件、Prospect 和观察记录，不再导出或恢复已退役的旧记忆和旧情绪表。仍兼容旧格式的其他数据：无新状态时按明确初值建立，恢复处理中任务时清除租约。会话线程配置继续保留。

重构首轮回归 111 项测试通过；退役清理后增加启动不重建旧表、重复清理和旧备份不恢复旧表的测试，完整回归 113 项通过，`compileall` 通过。验收使用临时数据库和模拟模型，覆盖契约、阈值/衰减、GET 只读、幂等、租约、失败重试、Prospect、TTL、消息事务、备份与语料隔离，同时运行已有记忆测试。尚未进行真实模型端到端、长期运行、延迟与前端验收；同步 Appraisal / Need 调用可能增加回复延迟。

首版重构时未操作真实数据库。后续用户明确授权停机清理，已停止 8000 端口后端，清理主库与历史备份中的旧表，并对主库其余 75 张表、备份其余 30 张表进行逐表内容摘要比对，结果一致；SQLite 完整性检查通过。使用 secure_delete、VACUUM 和 WAL 截断清理数据库残留页；这不构成 SSD / 系统快照层面的取证安全擦除保证。没有另留旧数据恢复副本，当前工作区内无法通过原历史备份恢复旧表。
