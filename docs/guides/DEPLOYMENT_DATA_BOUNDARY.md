# 代码发布与使用数据的边界

目标：本地继续开发，VPS 独立保存真实使用数据；发布新代码不覆盖线上存档。本文保留最初的分类设计，当前已实施的本地目录和使用方式以[持久数据与代码发布](PERSISTENT_STORAGE.md)为准；VPS 尚未配置。

## 六类内容

| 类别 | 项目内容 | 发布时的处理 |
|---|---|---|
| 版本代码和默认资源 | backend、mobile、tools 的源码，维护脚本，第三方程序和许可证，默认提示词、人设模板、版本管理的角色语料、默认世界规则、应用自带图像音视频 | 随版本更新，只写入 app |
| 永久使用数据 | 所有实际业务数据库、生活存档、消息邮箱、情绪、记忆、聊天、日程、重要日期、手机同步状态、私人书籍与阅读进度、上传附件、私人房间视频、自建歌单、模型账本和暂停记录 | 独立放 data，代码发布不覆盖、不清空、不重置 |
| 公共参考数据 | 工作日/节假日/调休表、随版本提供的阅读影视知识、默认角色语料和规则模板 | 可随代码提供数据包，通过专用更新流程导入；不得用本地完整数据库替换线上数据库 |
| 环境配置和凭据 | 服务地址、模型配置、密钥、Firebase 凭据、第三方登录、CLI 认证、运行参数；发布签名密钥另存构建环境 | 单独放 config 或部署环境的受控配置，开发与线上各自维护 |
| 缓存与诊断 | 可重建检索索引、向量缓存、缩略图、音乐缓存、普通日志、临时任务输出和构建缓存 | 可重建内容单独保留或清理；不得把模型账本、任务队列、原始记忆当缓存 |
| 备份 | 一致性数据库备份、媒体备份、迁移前快照和恢复记录 | 单独保留，并有 VPS 之外的副本；不进入代码发布目录 |

手机上的未同步专注记录、本地头像和设置仍是持久使用数据，位置在手机。服务器升级不应触碰它们；更换手机或重装 App 需要独立同步/备份。

## 推荐目录

```text
/srv/libra/
├── app/                 # 发布目标：代码、第三方程序、默认资源
├── data/                # 持久使用数据，普通发布禁止写入
│   ├── libra.db
│   ├── content.db
│   ├── cognition.db
│   ├── life/            # 世界状态、生活记忆、日程、邮箱、调用账本
│   ├── uploads/         # 用户和左然的实际媒体
│   ├── private_reading/ # 私人书籍、解析产物、阅读进度
│   ├── room_media/      # 私人影片等
│   ├── music/           # 自建歌单数据库、音乐组件的非缓存数据
│   └── overrides/       # 使用中修改的人设、提示词、规则等持久覆盖值
├── config/              # VPS 专用环境设置和凭据
├── cache/               # 确认可重建的缓存
├── logs/                # 普通运行日志
└── backups/             # 本机备份，另同步一份到其他存储
```

这是目标布局，并非当前程序已全面支持的目录。发布操作限定到 app，不能同步整个 `/srv/libra/`，不能让镜像替换、目录删除或清理命令覆盖 data/config/backups。使用容器时这些目录必须在可替换容器之外持久化。

## 当前持久数据位置及目标

| 当前位置 | 目标分类/位置 |
|---|---|
| `backend/libra.db`、`content.db`、`cognition.db` | `data/`；每个库整体保留，不能按“属于左然还是用户”拆着覆盖 |
| `backend/life/` | `data/life/`；含生活主库、消息邮箱、运行账本和暂停标记 |
| `backend/uploads/` | `data/uploads/`；缩略图可在路径统一后另分缓存 |
| `backend/private_reading/` | `data/private_reading/` |
| `backend/room_media/` | `data/room_media/` |
| `third_party/netease-music-mcp/music.db` | `data/music/music.db`；实际包含 playlists、playlist_songs |
| `third_party/Music-Mcp-Netease/server/data/` | 非缓存 JSON 等放 `data/music/`，music_cache 放 cache |
| `backend/.env`、`backend/secrets/`、音乐凭据及 CLI 认证 | VPS 专用 config/环境配置；不随本地发布覆盖 |
| `backend/backups/`、生活迁移备份 | backups；保留需要恢复的版本 |
| `backend/logs/` | logs |
| `backend/xhs_runs/`、`output/` | 按内容判定：私人导出和需保留的审计进 data/backups，临时诊断进 logs/cache |
| `libra/`、persona/prompts/config 中的默认内容 | 默认内容随版本；实际使用中修改的内容作为 data/overrides 或数据库记录保留 |
| 手机应用私有目录及 SharedPreferences | 手机侧数据，先确保同步；本机路径不直接迁移为云端文件地址 |

节假日数据目前位于 `libra.db/work_calendar`，也随线上数据库保留。以后更新某年的官方日历应只更新对应参考数据，并明确保留用户自行调整的规则；当前没有宣称已实现覆盖值分层。

## 本地开发和线上运行

- 本地：本地代码 + 本地开发配置 + 开发数据库。
- VPS：已发布代码 + VPS 配置 + VPS 持久数据。
- 本地日常开发不直接连接线上可写数据库。需要复现问题时使用独立备份副本。
- 第一次上云才迁移现有完整使用数据。切换前停止旧实例的写入并取得一致性快照，核对数据库、附件、生活状态和音乐歌单，再切换手机地址。
- 后续发布仅交付代码及默认资源，不上传本地 `.db`、生活目录或用户媒体覆盖线上内容。

## 数据库版本更新

更新功能可能新增表或字段，因此“只替换代码”还需要受控的数据库迁移：

1. 在线上备份和独立副本上验证迁移，记录代码与 schema 版本。
2. 正式更新前制作一致性备份；迁移时暂停写入，确保只有一个写入实例。
3. 执行可重复、安全的增量迁移，保留已有记录；不使用开发库覆盖生产库，不重建已有生活实例。
4. 验证接口、生活配置指纹、附件访问、歌单和关键业务数据。
5. 代码回退需确认数据库兼容；恢复旧快照会失去快照之后的新数据，不能自动当作无损回滚。

固定人设和世界配置参与生活引擎的版本校验。更新角色模板不应偷偷替换已经运行的角色配置；改变存档中的设定需要显式、可追踪的迁移。

## 当前尚需改造

- `infrastructure/paths.py` 已有 `LIBRA_RUNTIME_DIR`，但默认仍把数据放在 backend。
- 书房仍使用源码相对路径 `backend/private_reading`。
- 小红书素材路径仍指向源码树中的 `backend/uploads/xhs`。
- 自建歌单数据库及音乐服务数据仍写在 third_party 内。
- 环境变量必须在各模块计算路径之前加载；目前 runtime 加载 `.env` 时已经导入路径模块，不能只改 `.env` 就假定迁移全部生效。
- 凭据、缓存、日志、备份和默认资源/用户覆盖值还未统一独立配置。
- Linux 部署还要适配 Windows 计划任务、可执行文件和本机路径。
- 现有私人 ZIP 导出不是完整迁移包，应补齐上述持久数据及恢复验证。

完成这些改造并验证跨版本升级后，才能把“不覆盖使用数据”变成可检验的发布流程。`.gitignore` 只约束 Git 收录，不会防止整目录上传覆盖数据。
