# 左然的电脑端 Open-LLM-VTuber 接入实验

Open-LLM-VTuber 提供电脑页面、屏幕图片输入和语音输出，回复通过现有 Libra HTTP 对话接口生成。它沿用后端的人设、记忆、生活状态和对话存档，不将 VTuber 自带角色提示词发送给模型。

## 当前边界

- 支持用户文字（或 VTuber 已转写的语音）及同一回合最新一张屏幕图片。
- 回复交给 VTuber 显示和朗读；朗读声音取决于其 TTS 配置，并不自动等于左然的声音。
- 屏幕图片走现有聊天上传接口，会保留在项目聊天记录中；只在用户发送消息时上传，当前不会后台持续截图。
- 主动讲话输入暂时跳过，避免把系统观察伪装成用户发言写入记忆。持续观影、自动评论和剧情短期缓存尚待实现。
- 前端中断会丢弃本次迟到回复，但不能撤回后端已生成或已保存的内容。
- VTuber 的新建/切换历史不会清空或切换 Libra 的长期记忆。此启动器的所有角色配置均接同一个左然 Agent，建议只单人单窗口使用。
- 后端目前是完整回合返回，不是逐字流式输出，延迟需要实测。

## 环境与运行

上游：<https://github.com/Open-LLM-VTuber/Open-LLM-VTuber>

已下载版本：v1.2.1，提交 `992309c0aa19845960228f880013d4685fde93b5`；含前端子模块。上游要求 Python 3.10–3.12，应使用独立环境，不要覆盖左然原有 Python。

完成上游官方依赖和 `conf.yaml` 中语音识别、语音合成配置后，用上游环境的 Python 启动本适配器：

```powershell
python E:\LIbra-companion\tools\vtuber_bridge\run.py --libra-url http://127.0.0.1:8000
```

默认从 `third_party/Open-LLM-VTuber` 启动；可用 `--vtuber-dir` 指定其他独立安装目录。现有左然后端应先启动。首次配置页面建议绑定 `127.0.0.1`，端口使用上游默认 `12393`。

在电脑页面输入文字检查回复，再在屏幕共享里选择电影窗口，发消息检查图片是否随回合到达。不要同时启动上游 `run_server.py`，直接运行它不会使用本适配器。

## 验证

```powershell
python -m unittest discover -s tools/vtuber_bridge -p 'test_*.py' -v
```

测试使用模拟 HTTP，不调用真实模型、不写个人记忆；Agent 合约测试导入已下载上游的真实输入/输出类型。通过这些测试不等于已完成语音、屏幕共享或连续观影的端到端验收。
